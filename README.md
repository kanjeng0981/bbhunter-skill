# bbhunter

AI-powered bug bounty hunter agent for **web2 + web3**, running a full
pipeline: **recon → scan → validate → report**.

> ⚠️ **Authorized testing only.** Only point this at targets you own or have
> explicit permission to test (bug bounty program scope, labs, CTFs).
> Unauthorized scanning is illegal and violates program rules.

## Features

- **Web2**: passive subdomain enumeration (crt.sh), HTTP probing, tech
  fingerprinting, and safe GET-based checks (exposed files, missing security
  headers, server disclosure, SQLi error hints, reflected-XSS canary).
- **Web3**: Ethereum JSON-RPC recon (chain id, bytecode, balance), verified
  source fetching (Etherscan), and LLM-driven Solidity vulnerability analysis
  plus opcode heuristics.
- **LLM triage**: findings are reviewed by the LLM to prune false positives and
  calibrate severity/confidence/CVSS.
- **Skills**: drop Markdown playbooks into `skills/` to steer the agent.
- **Reports**: Markdown output sorted by severity.

## Install

```bash
cd bbhunter
python3 -m venv .venv
. .venv/bin/activate
pip install -e .
```

## Configure

```bash
cp .env.example .env   # then edit .env
```

At minimum set `BBHUNTER_LLM_BASE_URL` / `BBHUNTER_LLM_MODEL` (and
`BBHUNTER_LLM_API_KEY` if your endpoint needs one). Defaults point at an
OpenAI-compatible endpoint.

## Usage

```bash
# Full pipeline (web2 + web3)
bbhunter run -t example.com -c 0x1234... --chain ethereum

# Web2 only
bbhunter run -t example.com --web2-only

# Web3 only, skip LLM triage
bbhunter scan -c 0x1234... --chain polygon --no-validate

# Recon only
bbhunter recon -t example.com

# List loaded skills
bbhunter skills
```

Reports are written to `reports/` (configurable via `BBHUNTER_OUTPUT_DIR`).

## Skill format

A skill is a Markdown file in `skills/` with optional frontmatter:

```markdown
---
name: my-playbook
description: what it teaches the agent
scope: web2 | web3 | both
---
...instructions / checklists...   # injected into LLM prompts

## References
...links / attribution...       # human reference, NOT injected
```

Skills are filtered by `scope` and, when the catalog is large, selected by
relevance to the current findings so prompts stay bounded.

`skills/recon/` is a distilled import of ~100 field-tested playbooks from
[uphiago/recon-skills](https://github.com/uphiago/recon-skills) (MIT),
generated by `scripts/import_recon_skills.py`. Re-run it against a fresh
clone to refresh the catalog.

`skills/hack/` is a distilled import of deep web/web3 playbooks from
[yaklang/hack-skills](https://github.com/yaklang/hack-skills) (MIT),
generated by `scripts/import_hack_skills.py`.

## Write-up reference

`REFERENCE.md` is a full, categorized list of public bug-bounty write-ups
(from https://github.com/ngalongc/bug-bounty-reference). Skills inject
per-category checklists into the LLM; this file is the intact human-readable
reference.

`REFERENCE-evm-fuzzing.md` is a curated list of EVM fuzzing resources (tools,
articles, benchmarks, reusable ERC properties) from
https://github.com/perimetersec/evm-fuzzing-resources.

## Project layout

```

├── bbhunter/
│   ├── cli.py            # Click CLI
│   ├── agent.py          # pipeline orchestrator
│   ├── llm.py            # OpenAI-compatible client
│   ├── config.py         # env-driven settings
│   ├── models.py         # Finding/WebHost/ContractInfo

│   ├── pipeline/         # recon, scan, validate, report
│   └── modules/
│       ├── web2/         # subdomain, probe, tech, checks

├── REFERENCE.md          # full categorized write-up list
└── REFERENCE-evm-fuzzing.md  # EVM fuzzing resource list
```
